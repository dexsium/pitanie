# Питание — дневник калорий, БЖУ, воды и активности (Flutter)

Local-first приложение для Android и iOS: питание по приёмам пищи, свои продукты и
блюда, вода, вес, статистика, календарь, активность с Amazfit GTR 4 через
Health Connect / Apple Health, резервные копии, уведомления.

## Статус

Код написан целиком, но **на момент написания не компилировался и не
запускался**: на машине разработки не был установлен Flutter. Первая сборка в
GitHub Actions покажет ошибки компиляции, если они есть. Ничего из этого списка
нельзя считать проверенным, пока CI не станет зелёным, а приложение не будет
запущено на телефоне.

## Сборка

Требуется Flutter stable (Dart ≥ 3.4).

```bash
bash tool/prepare.sh   # flutter create, pub get, build_runner, настройка разрешений
flutter test
flutter run
```

`tool/prepare.sh` создаёт папки `android/` и `ios/` (их нет в репозитории),
генерирует код Drift (`*.g.dart`) и правит манифесты (`tool/setup_platforms.py`):
разрешения Health Connect, камера, уведомления, `FlutterFragmentActivity`,
minSdk 26, entitlements HealthKit.

На Windows запускайте скрипт из Git Bash или WSL (нужны bash и python3).

### GitHub Actions

`.github/workflows/build.yml`: тесты → APK (`pitanie-apk`) → неподписанный IPA
(`pitanie-ipa-unsigned`).

### iOS и HealthKit

Неподписанный IPA нужно подписать самостоятельно. Возможность HealthKit требует
App ID с включённой возможностью HealthKit, то есть платного аккаунта Apple
Developer. Бесплатный Apple ID HealthKit не поддерживает: приложение будет
работать, но экран «Устройства» не получит данные.

## Структура

```
lib/
  app/                 оболочка, тема, провайдеры Riverpod
  core/                чистая логика: расчёты, даты, защита от двойного счёта
  database/            Drift: таблицы, запросы, миграции, стартовый справочник
  features/
    dashboard/ nutrition/ products/ recipes/ water/ weight/
    activity/ health_integration/ statistics/ calendar/ profile/ settings/
  shared/              общие виджеты
test/                  расчёты, агрегатор активности, база данных, бэкап
docs/AMAZFIT_REPORT.md технический отчёт по источникам данных часов
```

## Что реализовано

* Главная, Питание (4 приёма пищи), Активность, Статистика (день/неделя/месяц),
  Профиль; Вода, Вес, Календарь, Устройства, Мои блюда, Настройки.
* Продукты: каталог, поиск без учёта регистра (в том числе для кириллицы),
  категории, избранное, недавние, свои продукты, количество в г/мл/порциях/штуках.
* Блюда: расчёт на 100 г и порцию, масса готового блюда, копирование,
  избранное; в дневнике хранится снимок пищевой ценности.
* Сканер штрихкодов; онлайн-поиск (Open Food Facts) только с согласия и только
  по штрихкоду.
* Два режима цели: фиксированная (по умолчанию) и динамическая без двойного
  учёта активности.
* Резервная копия JSON с SHA-256, восстановление, экспорт CSV.
* Локальные уведомления.

## Ограничения и честные оговорки

* **Справочник продуктов**: встроено около 37 типовых продуктов (значения
  USDA и общепринятых таблиц, источник указан в записи). Для точного учёта
  сверяйте с упаковкой или создавайте свой продукт. Полноценные справочники
  нужно импортировать отдельно (импорт CSV каталога в первой версии
  не реализован).
* **Amazfit**: прямое BLE-подключение не реализовано (см. отчёт). Какие
  показатели реально приходят, зависит от версии Zepp; проверьте на экране
  «Устройства → Диагностика».
* **Фоновая синхронизация** не реализована: данные догружаются при запуске,
  возврате в приложение и вручную.
* **Миграции БД**: схема версии 1, механизм миграций (`onUpgrade`) подготовлен,
  но реальных миграций ещё нет, поэтому и теста миграции нет.
* Расчётные нормы ориентировочные и не заменяют консультацию специалиста.
