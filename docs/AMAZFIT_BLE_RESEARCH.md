# Amazfit GTR 4 по BLE: результаты исследования (этап 1)

Источники: репозиторий Gadgetbridge (зеркало на GitHub, ветка master), gadgetbridge.org.
Код Gadgetbridge не копировался.

## Подтверждено по исходникам
- **Лицензия: AGPLv3.** Перенос кода в наше приложение обязывает открыть весь исходник приложения под AGPLv3
  и несовместим с закрытой публикацией. Реализация должна писаться независимо, по протоколу. Решение о лицензии за вами.
- **Имя устройства:** `Amazfit GTR 4` (`HuamiConst.AMAZFIT_GTR4_NAME`). Часы относятся к Zepp OS (`ZeppOsCoordinator`).
- **Поддержка в Gadgetbridge:** «Highly supported». Проверенные прошивки: 3.8.5.1, 3.17.0.2, 3.18.1.1.
- **GATT (HuamiService.java):** сервисы `0000fee0-…`, `0000fee1-…` (базовый UUID Bluetooth), `0000180d-…` (Heart Rate);
  характеристики `0000000N-0000-3512-2118-0009af100700`:
  `…0009` — авторизация, `…0005` — данные активности, `…0006` — батарея, `…0007` — шаги в реальном времени,
  `…0010` — события устройства, `…0016` / `…0017` — chunked 2021 (запись / чтение), `…0020` — chunked,
  `…0023` — передача файлов Zepp OS v3.
- **Chunked 2021:** «эндпоинты» сервисов внутри протокола: батарея `0x0029`, пульс `0x001d`, шаги `0x0016`,
  тренировка `0x0019`, авторизация `0x0082`, соединение `0x0015`, профиль `0x0017`.
  Часть эндпоинтов шифруется AES (`Huami2021ChunkedEncoder`), ключ — тот самый authKey.
- **Типы данных для выборки истории (HuamiFetchDataType):** активность `0x01`, ручной пульс `0x02`,
  итоги тренировок `0x05`, детали тренировок `0x06`, SpO₂ `0x25` / сон `0x26`, стресс `0x12`/`0x13`,
  PAI `0x0d`, пульс покоя `0x3a`, макс. пульс `0x3d`.

## Ключ авторизации
Ключ создаётся при сопряжении в приложении Zepp и хранится на серверах Zepp. Gadgetbridge: «локально
сгенерировать ключ нельзя». Способы получения: вход в аккаунт Zepp + интернет (скрипты/утилиты),
root-доступ к базе Zepp, логи приложений Xiaomi. **Вывод: первая привязка без Zepp невозможна.**
Нужны: аккаунт Zepp, часы, сопряжённые с Zepp, и интернет один раз. После этого прямое подключение
по BLE возможно, пока вы не отвяжете часы в Zepp (иначе ключ меняется).

## Не изучено (требует отдельной работы, не придумываю)
- Точная схема рукопожатия авторизации Zepp OS (порядок сообщений, формат ответов): нужно читать
  `ZeppOsSupport`/сервис авторизации и сверять с реальным BLE-логом.
- Форматы пакетов активности, сна, SpO₂, тренировок, расписание синхронизации.
- Включение шифрования отдельных эндпоинтов на GTR 4: список приходит от часов при подключении.

## Ограничения платформ
- Android: нужны `BLUETOOTH_SCAN`/`BLUETOOTH_CONNECT`; фон — только Foreground Service.
- iOS: нет MAC-адреса; фоновая работа CoreBluetooth ограничена, непрерывную синхронизацию обещать нельзя.
- Часы держат одно активное соединение: если подключён Zepp, наше приложение подключиться не сможет.

## Обновление: схема авторизации Zepp OS (по исходникам Gadgetbridge, InitOperation2021)
1. Подписка на уведомления характеристики 0017.
2. Приложение генерирует приватный ключ 24 байта, открытый ключ ECDH на кривой NIST B-163 (48 байт: x||y, little-endian)
   и отправляет в эндпоинт 0x0082 сообщение `04 02 00 02` + открытый ключ (chunked, без шифрования).
3. Часы отвечают `10 04 01` + случайные 16 байт + их открытый ключ (48 байт).
4. Общий секрет S = ECDH(приватный, чужой публичный). Начальный счётчик = первые 4 байта S (LE).
   Ключ сессии = S[8..24) XOR секретный ключ Zepp (16 байт).
5. Приложение отправляет `05` + AES-ECB(random, секретный ключ) + AES-ECB(random, ключ сессии).
6. Ответ `10 05 01` — успех, `10 05 25` — ключ отклонён.
Дальше сообщения шифруются AES-ECB с ключом (ключ сессии XOR номер сообщения), с хвостом: счётчик + CRC32.
Статус в нашем коде: реализовано и проверено юнит-тестами (математика ECDH, AES, CRC32, сборка пакетов);
совместимость с реальными часами ещё не проверена.
