Отчёт составлен по коду репозитория. Работа приложения на устройствах здесь не проверялась: где вывод сделан только по коду, это указано. Изменений в код на этом этапе нет.

## 1. Карта архитектуры

- **Стек:** Flutter 3.47.2, Riverpod (провайдеры в `lib/app/providers.dart`), Drift + SQLite (файл `pitanie.sqlite`, схема v4), `health` 13.x (Apple Health / Health Connect), `flutter_blue_plus` (только весы), `flutter_local_notifications`, `fl_chart`, `pdf`/`printing`, `mobile_scanner`, `flutter_secure_storage`, `image_picker`, `http`.
- **Слои:** `lib/core` (расчёты норм: BMR/TDEE/макро/вода/тренд веса), `lib/database` (таблицы, миграции, запросы), `lib/services/health/plan_service.dart` (снимок плана), `lib/features/*` (экраны и логика по разделам), `lib/shared/widgets.dart` (общие компоненты), `lib/app/theme.dart` (тема).
- **Навигация:** нижнее меню из 5 вкладок (Главная, Питание, Активность, Статистика, Профиль) в `lib/app/app.dart`. Не менялось.
- **Таблицы БД:** users, products, recipes, recipe_ingredients, food_entries, water_entries, weight_entries, activity_records (уникальность по type+source+externalRecordId), workouts, lift_* (4), daily_goals (с датой вступления в силу), connected_sources, app_settings.
- **Каталог продуктов:** встроенный `catalog.sqlite` (4,2 МБ): 13 224 позиции USDA (SR Legacy + FNDDS), на русский переведено 499. Штрихкод: Open Food Facts онлайн, найденный продукт сохраняется локально.
- **Источники данных о здоровье:** `health_service.dart` читает Apple Health / Health Connect. Прямой Bluetooth к часам удалён в 1.21.0. Bluetooth остаётся только для весов Mi (`features/scale`).
- **Резервная копия:** `backup_service.dart`, JSON формата 1 с контрольной суммой SHA-256.
- **ИИ:** Gemini по ключу пользователя (распознавание еды по фото, совет «чем добрать»), ключ в защищённом хранилище.
- **CI:** `.github/workflows/build.yml` (анализ, тесты, APK), `ios-testflight.yml` (подписанная IPA в TestFlight). Папки `ios/` и `android/` в git не хранятся, создаются `tool/prepare.sh`.

## 3. Конфликты и решения, которые нужны от вас

1. **ТЗ и ваша просьба разошлись:** ТЗ просит сохранить индекс восстановления и анализ HRV, а вы раньше попросили полностью убрать «Анализ здоровья». Предлагаю считать приоритетной вашу последнюю прямую просьбу (не возвращать). Подтвердите.
2. **Умный будильник** в проекте не существует; в ТЗ он значится как существующая функция. Предлагаю не делать (требует системных будильников и точности, которую нельзя гарантировать).
3. **Виджеты на iOS:** нужны нативный код и расширение Xcode, а `ios/` создаётся в CI. Это возможно, но самое рискованное по сборке место.
4. **Реклама:** выбор сети и юридические требования (согласия, App Store / Google Play) за вами; код можно подготовить с заглушкой «рекламы нет», без SDK.

### Принятые решения
1. Анализ здоровья, индекс восстановления и анализ HRV не возвращаются.
2. Умный будильник не делается.
3. Виджеты iOS и Android выделены в отдельный этап.
4. Реклама делается по ТЗ (этап 7); сеть и SDK выбираются перед подключением, данные здоровья в рекламу не передаются.

## 5. Схема данных здоровья (целевая)

Источник (Apple Health / Health Connect) → `HealthService.sync()` → запись в `activity_records` / `workouts` / (вес) `weight_entries` с полями: тип, интервал, значение, единица, платформа, id приложения-источника, id записи, время изменения, происхождение → выбор одного источника на тип и день (по умолчанию наибольший объём; ручной выбор в «Источниках здоровья») → экраны. Удаления: Health Connect Changes API / HealthKit anchored query помечают записи удалёнными.

## 6. Технические риски

- Фоновая синхронизация на iOS ограничена системой (не гарантирована по времени), на Android зависит от режимов энергосбережения.
- Новые типы Health требуют повторного запроса разрешений (iOS покажет окно один раз).
- Данные с часов попадают в Здоровье только если приложение часов их туда пишет (Zepp). Мы не можем это гарантировать.
- Виджеты iOS: расширение Xcode в CI без постоянной папки `ios/`.
- Реклама и конфиденциальность: требования магазинов и согласий нужно проверить до включения.
- Причина сбоя весов Mi «не с первого раза» не найдена; нужен журнал.
- Заявленная «поддержка» чужих весов без устройства для проверки будет недостоверной: драйверы добавляем только для проверенных протоколов.
