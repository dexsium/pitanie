# Этап 3. Умные весы (отчёт)

## Что сделано
- `lib/features/scale/scale_driver.dart`: интерфейс драйвера (`id`, `title`, `verified`, `transport`, `matches`), модель измерения `ScaleMeasurement` (все показатели необязательны, отсутствующие остаются пустыми), реестр драйверов и выбор по рекламным данным.
- Драйверы:
  - `MiScale2Driver`: Mi Body Composition Scale 2, данные в рекламе. **Проверен на устройстве.** Прежняя логика (`mi_scale.dart`, `ScaleController.onReading`) не менялась.
  - `StandardGattScaleDriver`: весы со стандартными сервисами Bluetooth SIG (Weight Scale 0x181D, Body Composition 0x181B) с подключением. **Не проверен на реальных весах**, помечен «не проверен» в интерфейсе.
- `standard_scale.dart`: разбор характеристик 0x2A9D (вес, время, пользователь, фунты/кг) и 0x2A9C (жир, мышцы, вода, обмен веществ, импеданс, вес). Невалидные значения (0xFFFF), обрезанные и многочастные пакеты отбрасываются, ничего не подставляется.
- `gatt_scale.dart`: подключение, поиск характеристик, подписка, сбор измерения (ждёт паузу 4 с после последнего значения, окно 40 с), отключение.
- `ScaleController`: выбранные пользователем весы подключаются, когда появляются в эфире; до 3 попыток с паузой; пауза 30 с после измерения; защита от повторного сохранения одного измерения (±0,05 кг, 120 с); результат показывается в том же окне «Измерение веса».
- `scale_setup_page.dart`: поиск совместимых весов, выбор и «Забыть», список драйверов с отметкой «проверен / не проверен».
- База (схема 5, ещё не выпущена): в `weight_entries` добавлены `muscleMassKg`, `bodyWaterKg`, `bmrKcal`, `scaleDriver`; жир и безжировая масса используют столбцы этапа 2.
- Дубли с Health: `saveScaleWeight` дополняет уже импортированное из Здоровья измерение вместо добавления (этап 2).
- Тесты: `scale_drivers_test.dart` (пакеты, собранные по спецификации), состав тела в базе.

## Чего нет и что важно знать
- **Костная масса и висцеральный жир** в стандартных сервисах Bluetooth отсутствуют, они приходят только по собственным протоколам производителей. Драйверов для них нет, потому что нет проверенной документации; значения не выдумываются.
- **ИМТ** по-прежнему считается по росту и весу в приложении, весы его не используются.
- **Отображение состава с весов** (жир, мышцы, вода) на экране «Состав тела» и графиках относится к этапу «Статистика веса»: данные уже сохраняются.
- **Потеря соединения и повторное подключение**: реализовано (попытки, пауза), но на реальных весах не проверено.
- **Фон**: как и для Mi, весы читаются только пока приложение открыто (iOS не отдаёт пакеты свёрнутому приложению).

## Лицензия Bluetooth-библиотеки
Для `connect()` библиотека `flutter_blue_plus` 2.x требует указать лицензию. По вашему решению указана `License.nonprofit` (личное и некоммерческое использование). Условия библиотеки требуют коммерческую лицензию для любого коммерческого использования, в том числе организациями, получающими доход. **Когда будет подключена реклама (этап 7), это нужно пересмотреть:** либо купить коммерческую лицензию, либо перейти на библиотеку с лицензией BSD (например, `flutter_reactive_ble`). Решение за вами.
