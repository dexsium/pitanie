# Этап 4. Питание, рецепты, база продуктов (отчёт)

## Уточнение к аудиту
Часть функций из ТЗ уже была в приложении, аудит это недооценил: «Повторить вчерашний приём пищи» и «Копировать из другого дня» (по приёму пищи), вкладки «Избранное» и «Недавние», правка записи с пересчётом КБЖУ, редактор блюд с массой готового блюда и порциями, КБЖУ на 100 г и на порцию. Эти части не переписывались.

## Что не сделано и почему
- **Коэффициенты изменения при готовке.** Достоверной таблицы коэффициентов в проекте нет, выдумывать их нельзя. Расчёт блюда по-прежнему берёт калорийность из сырых ингредиентов, а масса готового блюда влияет на КБЖУ на 100 г. В редакторе это пояснено.
- **База продуктов российского рынка.** Встроенный каталог это USDA (13 224 позиции, русские названия у 499). Добавить российские продукты можно только из лицензионно чистого источника; сейчас они приходят по штрихкоду из Open Food Facts онлайн и сохраняются локально. Отдельного набора российских товаров в этом этапе нет.
- **Статус проверки.** Используются уже существующие признаки: `verified` (значение из официального справочника) и `source`. Отдельный многоступенчатый статус не вводился.
- **Кеширование популярных товаров** отдельно не делалось: продукты, найденные по штрихкоду, уже сохраняются в базу и доступны офлайн.
- Не проверялось на устройстве: меню, окна и кнопки проверены анализом и тестами логики, не вручную.
