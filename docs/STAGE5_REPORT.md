# Этап 5. Надёжность данных (отчёт)

## Что сделано
- **Формат резервной копии 2** (`backup_service.dart`): добавлены версия схемы базы и число записей по таблицам; при чтении проверяются структура, версия, контрольная сумма SHA-256 и число записей. Копии формата 1 читаются (недостающие поля получают значения по умолчанию). Копия от более новой версии приложения отвергается понятным сообщением. Для будущих несовместимых изменений есть реестр шагов `_migrations` (формат N → N+1).
- **Безопасное восстановление:** файл сначала полностью разбирается без изменения базы; затем делается снимок текущих данных (три последних хранятся в папке `backups` приложения); замена выполняется в одной транзакции. Повреждённая строка не стирает данные (проверено тестом).
- **Состав копии:** дневник, блюда, шаблоны, продукты, вода, вес и состав с весов, активность, тренировки, дневник силовых, цели с датами вступления в силу, настройки. Ключи ИИ и токены хранятся в защищённом хранилище, не в базе, и в копию не попадают.
- **Удаление данных:** «Настройки → Данные → Удалить все мои данные» (два подтверждения). Удаляются все пользовательские данные, подключённые источники, настройки и ключ ИИ. Встроенный справочник остаётся, у его продуктов сбрасываются избранное и счётчик использования. Данные в Apple Health / Health Connect не затрагиваются.
- **Проверка целостности:** «Проверить целостность данных» (SQLite integrity_check и проверка связей).
- **Индексы** для больших историй: продукт и приём пищи в дневнике, тип и время активности, время веса. Создаются при создании базы, обновлении и открытии (IF NOT EXISTS).
- **Конфиденциальность:** текст в настройках о сетевых запросах приведён в соответствие (штрихкод и, если включён помощник, запросы к Gemini). В журналы медицинские данные не пишутся (`debugPrint` только про каталог продуктов).
- **Тесты** (`data_reliability_test.dart`, 11 штук): формат 2 и счётчики, новый формат, формат 1, повреждённая строка, снимки, удаление данных, целостность, переход через полночь, смена часового пояса, история целей, 60 тысяч записей (выборка за день быстрее 1,5 с).

## Что уже было и сохранено
- Все данные хранятся локально в SQLite, дневник, вода, вес, рецепты, статистика и тренировки работают без интернета. Запись в базу атомарна (SQLite), обрыв сети или закрытие приложения данных не теряют.
- История норм по датам вступления в силу (`daily_goals.effectiveDate`): новая цель не меняет прошлые дни (проверено тестом).
- Записи дневника хранят снимок КБЖУ.

## Ограничения
- **Удалённой синхронизации нет**: у приложения нет облачного хранилища, поэтому «синхронизация при появлении сети» неприменима; данные могут быть восстановлены только из файла копии.
- **Автоматические копии по расписанию** не делаются (только снимок перед восстановлением и ручной экспорт). Нужен либо системный планировщик, либо согласие пользователя на облако.
- **Часовые пояса:** календарный день записи хранится строкой в момент создания и не «плывёт» при смене пояса. Записи активности из Здоровья привязываются к дню по местному времени устройства, при смене пояса их распределение по дням может измениться; это ограничение не исправлялось.
- **Реклама и офлайн** относятся к этапу 7.
- Работа на устройствах не проверялась.
