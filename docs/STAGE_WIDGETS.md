# Виджеты главного экрана (отчёт)

## Что сделано
- **Локальный плагин `packages/pitanie_widgets`** (Android + iOS) без сторонних зависимостей. Приложение передаёт ему готовый JSON-снимок сегодняшнего дня, плагин сохраняет его локально и обновляет виджеты. Снимок никуда не отправляется, рекламным и аналитическим SDK не передаётся.
- **Android (полностью в репозитории):**
  - Малый виджет 2×1: остаток калорий, прогресс, «съедено из нормы».
  - Средний виджет 4×2: остаток калорий, прогресс, белки, жиры, углеводы, вода с прогрессом и кнопки «Вода», «Питание», «Вес».
  - Светлая и тёмная тема, изменяемый размер, обновление при изменении данных и раз в 30 минут.
  - Виджеты объявлены только для главного экрана (`home_screen`), на экране блокировки их нет.
- **iOS (WidgetKit):** малый и средний размер, тот же набор данных, кнопки «Вода», «Питание», «Вес» (ссылки `pitanie://widget/...`). Виджет только читает снимок, на экран блокировки не добавляется (поддерживаются только `systemSmall` и `systemMedium`).
- **Приватность:** показ данных в виджетах **выключен по умолчанию**; включается в «Настройки → Виджеты главного экрана». Пока выключено, виджет показывает подсказку и в снимке нет никаких данных о здоровье. «Удалить все мои данные» тоже отключает виджеты.
- **Нажатия:** виджет открывает приложение на нужном экране (питание, вода, вес, настройки).
- Тесты: `widget_snapshot_test.dart` (4 теста).

## Ограничения (честно)
- **Добавление воды одним нажатием без открытия приложения не реализовано.** Для этого нужен фоновый запуск Dart и доступ к базе из виджета; нажатие открывает приложение на экране воды. Это платформенное ограничение и осознанный выбор: случайные нажатия не меняют данные.
- **Данные виджета обновляются, когда приложение запущено или возвращается из фона**, и по таймеру системы (раз в 30 минут Android, ~30 минут iOS по расписанию WidgetKit, не гарантируется). Если вчерашние данные не обновлены, виджет просит открыть приложение.
- **Android собирается и проверяется в CI**, как и всё приложение. Локально проверялась сборка отладочного APK.
- **iOS-виджет НЕ включён в сборки по умолчанию и не проверялся.** Для него нужны действия в Apple Developer, которые не может сделать код:
  1. Создать App Group `group.com.pitanie.pitanie`.
  2. Включить App Groups в App ID `com.pitanie.pitanie` и пересоздать профиль App Store для него (обновить секрет `IOS_PROFILE_BASE64`).
  3. Создать App ID `com.pitanie.pitanie.widget` с App Groups и профиль App Store для него; положить его в секрет `IOS_WIDGET_PROFILE_BASE64` (base64).
  После этого сборка iOS сама добавит цель виджета (`tool/ios_widget/add_widget_target.rb`), внедрит её в приложение и подпишет. Пока секрета нет, шаги пропускаются и TestFlight собирается как раньше. Сценарий CI написан без возможности запустить его локально: при первом включении возможны правки по журналу.
- iOS-плагин (`PitanieWidgetsPlugin.swift`) собирается всегда; без группы приложений он возвращает `false` и ничего не сохраняет.
- Размеры «большой» и виджеты экрана блокировки не делались.
